# localAI 本地知识库测试文档

## 产品定位

localAI 是一个 Chrome 浏览器插件，用于调用 Chrome Built-in AI 在浏览器本地完成问答、总结和文本处理。它的核心目标是让用户的数据尽量留在本机，减少对云端模型和外部 API 的依赖。

localAI 当前不是一个模型训练工具。它不会预训练或微调 Gemini Nano，而是通过 Prompt API 调用 Chrome 内置模型，并通过本地知识库检索把相关资料拼接到 prompt 里。

## 本地知识库机制

localAI 的本地知识库采用 embedding 向量检索，并保留关键词评分作为兜底。用户导入 Markdown 或纯文本文件后，插件会把文档拆分成多个文本片段，为每个片段生成本地向量，并保存到 IndexedDB。

当用户提问时，插件会为问题生成查询向量，并通过余弦相似度从 IndexedDB 检索相关片段。检索到的片段会作为上下文附加到用户问题前面，再提交给 Chrome 内置 AI。模型回答时应该优先参考这些本地片段。

## 支持的文件类型

| 文件类型 | 是否支持 | 说明                                   |
| -------- | -------- | -------------------------------------- |
| `.md`    | 支持     | 推荐用于结构化知识、产品文档和技术笔记 |
| `.txt`   | 支持     | 推荐用于纯文本资料                     |
| `.pdf`   | 暂不支持 | 后续可以加入 PDF 文本解析              |
| `.docx`  | 暂不支持 | 后续可以加入 Office 文档解析           |
| 图片     | 暂不支持 | 当前知识库不做 OCR                     |

## Chrome Built-in AI 使用限制

Chrome Built-in AI 的 Prompt API 在部分版本中只支持 `en`、`es`、`ja` 作为声明的输出语言。即使用户使用中文提问，也可能需要在 API 参数里声明英文输出语言来满足 Chrome 的安全校验要求。

这不代表模型完全不能生成中文，而是说明当前 API 的语言声明能力仍有限。localAI 会通过中文 prompt 尽量引导模型使用中文回答。

## 后台执行机制

Chrome 插件 popup 关闭后，popup 页面会被销毁。如果 AI 推理只运行在 popup 页面里，用户关闭弹窗后任务就会中断。

localAI 使用 Manifest V3 的 background service worker 和 offscreen document 解决这个问题。用户发送问题后，popup 会先把会话状态保存为 `running`，然后把任务交给后台。后台创建隐藏的 offscreen 页面执行 Chrome Built-in AI，请求完成后再把结果写回 IndexedDB。

用户再次打开 popup 时，插件会读取最近一次会话。如果后台任务已经完成，用户可以看到 AI 回复；如果任务仍在运行，界面会继续显示 loading 状态。

## 常见问题

### localAI 会上传我的文档吗？

不会。第一版本地知识库把文档内容保存在浏览器 IndexedDB 中，检索也在本地完成。

### localAI 能回答知识库之外的问题吗？

可以。若检索不到相关片段，localAI 会直接把用户问题交给 Chrome 内置 AI。若检索到片段，回答应该优先参考本地知识。

### 为什么回答里会出现引用编号？

localAI 会把检索到的知识片段编号为 `[1]`、`[2]`、`[3]` 等，并提示模型在相关结论后标注引用编号。这样用户可以知道回答依据来自哪个本地文档片段。
